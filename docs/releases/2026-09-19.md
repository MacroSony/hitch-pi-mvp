# Release Note — 2026-09-19

This operator release note summarizes the public release baseline (version 0.1.0,
dated 2026-09-19). It documents the accumulated capabilities across the native
Pi runtime, channel transports, UX improvements, database schema evolution, and
host-local control.

## Commit and publication baseline

This update contains 30 development commits since the previous public main,
plus one public-release cleanup/documentation commit. An installation-specific
path was scrubbed from the unpublished history; no previously published commit
was rewritten. Existing phase-report hashes describe earlier operational builds
and are historical evidence, not necessarily reachable public commit IDs.

## Highlights and capabilities

### Pinned Pi 0.85.1 catalog and runtime
- Upgraded to pinned `@earendil-works/pi-ai` and `@earendil-works/pi-coding-agent`
  `0.85.1` with locked dependency closures.
- Startup catalog verification runs a bounded native `ModelRuntime` refresh
  against the canonical profile and securely propagates `models-store.json`
  across prepared user profiles without copying auth credentials.

### Manifest-based tool attestation and opt-in MCP
- Build-generated `dist/sandbox/tools-manifest.json` anchors expected tools and
  sandbox asset SHA-256 digests at build time.
- Shared `sandbox/manifest-attest.mjs` module standardizes tool-set verification
  across security extensions.
- Dynamic tool sources (such as the vendored `pi-mcp-adapter`, enabled via profile
  marker) are filtered by source path rather than hardcoded names, preventing late
  async activation from tripping attestation.
- Attestation ceremony operates with a single witness record and bounded failure
  reporting without per-execute re-verification overhead.

### Enterprise WeChat (WeCom) channel and attachment ingress
- Added a dedicated WebSocket channel worker (`ws` 8.21.3) with ping/pong liveness
  detection, exponential reconnect, and message deduplication.
- Supports private single chats with text and inbound media attachments (images,
  files, video, voice).
- Includes Content-Disposition filename recovery and CDN Content-Type MIME
  detection, plus notifications when staged attachments expire before a trigger
  text arrives.
- *Caveat:* Blanket native media egress across all media types is not claimed or
  verified for Enterprise WeChat; group callbacks are rejected before content work.

### In-session compaction turns (`!compact`)
- Introduced `!compact` command and maintenance turn lifecycle (`operation_kind: 'compact'`).
- Correctly honors Pi RPC compaction responses, appending compaction JSONL records
  and summarizing older context without deleting the stored transcript.
- `freshSession` is an explicit option for legacy wake schedules. External MCP
  wakes require a pinned existing session and do not reset its context.

### Per-user default Forge profiles
- Operators can configure a default Forge profile per user via
  `users[].forgeProfile`; explicit session profile/preset selection takes precedence.

### Shared operator auth authority
- All configured users share a single operator credential authority at
  `piProfileDir/auth.json` via `SharedCredentialStore` with atomic file replacements
  and `proper-lockfile` concurrency guards.
- Operator auth is never cloned into per-user directories at startup.

### Intermediate agent progress streaming
- Bounded streaming of agent text and tool-start previews to originating
  IM endpoints (at most one message per 30 seconds, max 4000 characters, 64 KiB total).

### Command formatting and context snapshots (UX-1)
- Grouped `!help` commands.
- Double-newline paragraph formatting for command responses, list displays, and
  status output.
- `!status` displays a durable, last-known session context usage snapshot (token
  metrics and context window percentage sampled from Pi session stats at the end
  of the last completed turn). Context status is advisory, not a live billing
  query.

### Host-local control and scheduling (LOCAL-1)
- Optional host-only authenticated Unix domain socket (`<dataRoot>/control/hitch.sock`),
  disabled by default.
- Official MCP SDK stdio adapter exposing seven scoped tools:
  - `hitch_targets`: list permitted users, endpoints, and sessions.
  - `hitch_notify`: send literal text directly to an outbox endpoint without a model turn.
  - `hitch_delivery_status`: inspect delivery outbox status.
  - `hitch_schedule_create`: schedule one-shot, daily, or weekly notifications or wake turns.
  - `hitch_schedule_list`: list caller-owned schedules and next fire times.
  - `hitch_schedule_set_enabled`: pause or resume existing schedules.
  - `hitch_schedule_cancel`: permanently cancel a schedule with a tombstone.
- Static caller scopes, caller-supplied request IDs for idempotency, disk admission
  checks, and safe crash recovery.
- When configuring manual stdio MCP clients, execute `node dist/src/local/mcp.js`
  directly (avoiding `npm run mcp`) so npm banner output does not corrupt the
  JSON-RPC protocol stream. See the [local-control runbook](../local-control.md).

## Database migration (Schema 8)

The active database schema is **Schema 8** (`hitch-pi-mvp-schema-8`).

Hitch automatically executes transactional migrations on startup from earlier
schema versions (schemas 1 through 7):
- Schema 3: `staged_artifacts` table.
- Schema 4: `sessions.forge_kind` and `sessions.forge_id`.
- Schema 5: Enterprise WeChat endpoint support.
- Schema 6: `compact` operation turns.
- Schema 7: nullable `sessions.context_usage` snapshot column.
- Schema 8: `local_requests` caller receipt table and restoration of the
  `turns_user_state_ordinal` FIFO index.

### Operator upgrade runbook
1. Stop the service cleanly: `systemctl --user stop hitch-pi-mvp.service`.
2. Take an owner-private backup of `<dataRoot>/hitch.sqlite` including WAL and SHM
   files (`hitch.sqlite-wal`, `hitch.sqlite-shm`), `config.json`, and `piProfileDir`.
3. Build the release: `npm ci && npm run acceptance:deterministic && npm run build`.
4. Start the service: `systemctl --user start hitch-pi-mvp.service`.

### Downgrade and recovery invariants
- **No code-only downgrade:** Code from older releases cannot read Schema 8 and
  will fail closed.
- **No automatic restore losing messages/auth:** Restoring a pre-upgrade database
  backup permanently discards new chat turns, outbox deliveries, and receipts.
  Never perform an automatic database restore without explicit data-loss agreement.
- **Auth recovery invariant:** The single authority is `piProfileDir/auth.json`.
  Legacy per-user auth files may remain but are not authoritative. **Never
  promote or restore a stale auth backup**, which can overwrite newly rotated OAuth refresh tokens and invalidate
  provider access. For recovery, stop the service and perform an attended re-login
  with pinned Pi 0.85.1 (`PI_CODING_AGENT_DIR=/srv/hitch/pi-profile node ...`).

## Validation and test evidence

- **Deterministic test suite:** 282 total tests: **264 passed, 18 skipped, 0 failed**.
  The opt-in tests were not run; this is not a substitute for host sandbox,
  real-provider or attended channel acceptance.
- **WeChat attended dogfood:** Operator-confirmed personal WeChat paragraph
  formatting and receipt of one immediate local-MCP notification; see the
  [dated follow-up acceptance](../ux-local-acceptance-20260919.md#subsequent-attended-personal-wechat-dogfood-2026-09-19).
- **WeCom testing caveat:** Enterprise WeChat media ingress and filename recovery
  are covered by transport tests, but blanket WeCom media ingress/egress is **not**
  all tested or verified in live production.
- **No full opt-in sandbox claim:** Deterministic suite passes verify isolation
  boundaries and attestation checks, but this release does not make a full opt-in
  sandbox host acceptance claim (which remains an attended host-level verification).

## Known issues and operational boundaries

- **`!send` suffixed-blob regression:** In this release, the chat command `!send`
  has a known regression handling suffixed blobs. The in-model tool `hitch_publish`
  functions correctly and should be used for workspace artifact publishing.
- **Debug sink cleanup:** Removed the one-off, installation-specific web-search
  file sink. Classified tool failures and existing runtime diagnostics remain.
- **WeChat send context:** Personal WeChat proactive notifications remain subject
  to platform send-context expiry windows.
- **Schedule capacity:** Stored schedule limit is 64 per user (including tombstones)
  to prevent unbounded JSON growth.
